# Sophiark — Current UI State Inventory

**Inspection date:** 2026-08-31  
**Scope:** current, source-backed Streamlit interface only; no scientific engine was changed or inspected for mathematical correctness.  
**Evidence:** source paths cited below, runtime launch prescribed by `readme.md:51` (`streamlit run app.py`), and a live local browser inspection of that entry point.  
**Status:** `UI_CURRENT_STATE_PARTIALLY_MAPPED`.

The shipped entry point is `app.py`; it is a single, wide, dark Streamlit screen with a persistent left sidebar and an in-flow, long scrolling main report. `src/ui/pages/00_home.py` through `04_ayarlar.py` implement a newer page set, but it is not registered by `app.py`, is not in the default Streamlit `pages/` directory, and the documented launch command does not expose it. It is therefore **ACTIVE_CONDITIONAL** only when launched directly/registered by another host, not a top-level screen of the documented product. This distinction is material: the active runtime screenshot shows `main.py aktif` and the monolithic result surface.

## 1. Executive current-state summary

The documented product has one active top-level screen (`app.py`) rather than route navigation. It is state-driven and button-driven: changes in the sidebar rerun Streamlit; a completed forward run causes the report hierarchy to render below the input/landing area. The root can run Classic, Directed BETA, Evidence BETA, or Compare (human); mouse offers Classic only. A single screen consequently combines configuration, run actions, results, Research Explorer entry, exports, history, and advanced tooling.

The live inspected state was Human / Adipose Tissue / Classic / Manual localization `Mitochondrion`. It confirmed the sidebar order, default tissue, controls, disabled single-target tools, a 30-row/22-column current result, and the result sections recorded below. It also confirmed that the default runtime can immediately present a result loaded/generated by its normal startup/run flow; this is not a separate landing page.

## 3. Screen inventory

### SCREEN: Root analysis workspace

**Entry:** application launch (`app.py`).  
**Purpose:** configure, run, inspect, export, and compare analyses in one scrollable screen.  
**Geometry:** Streamlit `layout="wide"`, expanded sidebar (`app.py:388-393`). Main content is full-width with sequential containers, occasional two/four-column metric groups, horizontal tabs, and nested expanders. No explicit content width or sticky control is defined.

**Fresh/top-to-bottom state:** sidebar appears first visually at left. The main area shows the Sophiark logo/header, `TISSUE-AWARE PROTEIN NETWORK ANALYSIS`, context (localization/target, tissue, species), graph-preparation status, then either a mode landing prompt or results. With no selected target, Target Stress and Compensation buttons are disabled; `Analizi Başlat` remains available for manual-localization mode. Missing target results show Turkish informational prompts. A graph/data failure uses a Streamlit error/warning and does not expose invented output.

This is the order of the root containers at `app.py:3922-4724`, and was confirmed in the live DOM.

## 4. New analysis journey (root)

1. Launch initializes defaults (`src/state.py:DEFAULTS`) and loads the species/tissue graph; the status changes from `Graf hazırlanıyor...` to `Graf hazır`.
2. Choose Human/Mouse, Turkish/English, tissue (default is the second human list item: `Adipose Tissue`), calculation engine, and target mode. A tissue selection activates the ghost-gene status; `None` disables tissue filtering.
3. Select one-to-ten genes, query disease targets, or choose a localization. Gene labels use `Symbol · ENSP`; resolved selections echo symbols and IDs.
4. Click `Analizi Başlat`. The app emits a status surface; it prepares graph/scores, runs the selected black-box engine, stores result/session history, and prepares enrichment. Exceptions produce an error.
5. Results render below the setup area. Changing species/tissue changes context and prevents stale context results from being treated as current; controls rerun Streamlit.
6. Optional actions run Target Stress, Compensation, Threshold Sweep, dose response, trace, tissue comparison, cross-species comparison, research context, disease context, or downloads. All are conditional on the associated live result/data.

## 6. Controls and state

All widgets invoke a Streamlit rerun. The most important result-bearing session keys are `rapor_df`, `workspace_report`, `workspace_graph`, `workspace_scores`, `workspace_targets`, `workspace_context`, `directed_run_bundle`, `signed_redistribution_result`, `enrichment_results`, `dose_df`, `sweep_df`, `propagation_trace`, `tissue_differential_result`, `target_stress_results`, `compensation_results`, `reports_by_species`, `unified_research_report`, and `saved_unified_result`. Presentation-only keys include locale, graph-node/label limits, display page/tab/radio keys, developer mode, export-format keys, and research selections. The definitive state map is `outputs/ui_inventory/session_state_map.json`.

State is session-scoped, not durable except for `.sophiark` history in the conditional multipage layer. `clear_active_workspace()` clears scientific result objects on context change; changing filters/tabs only changes presentation. Root history (`sim_gecmis`) retains at most ten in-session summaries and is explicitly legacy; it is not a durable bundle.

## 7. Tables and data density

`render_dataframe`/root alias `safe_dataframe` shows a maximum of 500 rows (unless a caller gives another `row_limit`), hides the DataFrame index, uses stretch width, exposes Streamlit's table search/column visibility/download affordances, captions total rows, and adds an in-place CSV/XLSX selector plus full-data download. Tables are vertically scrollable when a height is supplied; wide raw, Unified candidate, Classic raw, complex-context, and Research member tables require horizontal scrolling at normal desktop widths.

The complete source/column inventory is `outputs/ui_inventory/table_inventory.json`; it preserves display order, source fields, formatting and conditions. The 22-column live root response matrix was observed; full raw forward exports may have 76+ fields because engine/version/provenance fields are deliberately preserved. Representative real schema examples are based on the CFTR Unified CSV bundle and the current root forward report; no values were invented.

## 8. Research Explorer and persistence

Research Explorer is source-backed in `src/research/ui.py`. It starts only after the root button builds/binds a snapshot. Its horizontal segmented navigation is `Overview`, `Families`, `Functions`, `Relationships`. Overview shows five count metrics, member table, observation items, and optionally a directed-signaling table. The other lenses give a selectbox, then the selected item's summary, fields, members and source/provenance. One explicit download exports all Explorer tables as XLSX or CSV ZIP. Provider status/provenance stays export-only by design. Disease Context/Benchmark is in a separate closed root expander and is unavailable without the needed reference service.

The root does not show `.sophiark` open/import UI. That durable history/import workflow is **ACTIVE_CONDITIONAL** in `03_karsilastirma.py`, and is the only currently traced UI that reopens a full Unified report from a bundle.

## 9. Visual style inventory

Theme (`.streamlit/config.toml`) is dark: background `#090B11`, secondary surface `#141929`, text `#E6ECF7`, primary/accent `#589BFF`, sans-serif. `app.py` also applies `src/ui/ui_styles.py` / `design_tokens.py` CSS and extensive inline HTML. Root sidebar uses dark near-black panels, gray separators (`#2a2a2e`), compact uppercase/monospace labels, a white/yellow/red RAM bar, icons/emoji, status strips, and a white logo. Main content combines Streamlit headings with bespoke summary/readout/gene-card HTML. The source theme plus all extracted semantic colors are recorded in `style_inventory.json`.

Explicit inconsistencies: Turkish and English labels mix in one screen; `Gen`/`gene`/`Symbol`/`ENSP` vary by table; root visual implementation is mixed CSS/inline markup/component helpers; similar advanced tools occur in both sidebar and results; exports are repeated per table; metric conventions use legacy and canonical field names together.
